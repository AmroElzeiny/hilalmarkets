# 🧠 AI and Automation Boundaries

> **Workspace status:** Updated 17 July 2026. Product name: **HilalMarkets**.

## AI’s role

AI is a language and evidence-organization layer. It is not the market-decision engine, the Sharia authority, or the execution layer.

### Allowed
- Ask clarifying questions about a user’s desired market behavior.
- Retrieve a bounded shortlist of registered capabilities.
- Extract schema-defined parameters.
- Compile into a validated strategy definition.
- Organize retained factual evidence into a strict research schema.
- Explain deterministic results and stored evidence.
- Select from a server-offered, typed tool set when Bounded Agent Control is enabled.
- Propose a user-scoped candle-computable expression within the bounded JSON DSL.

### Prohibited
- Approve or activate a Watchlist.
- Set, change, approve, reject, or publish a Sharia status.
- Execute trades or place orders.
- Change billing, entitlements, or plan state.
- Generate or execute Python or arbitrary code.
- Call arbitrary URLs or invent evidence sources.
- Mutate the capability registry silently.
- Override identity, provider, ownership, policy, or data-quality checks.
- Convert missing evidence into eligibility.
- Claim hidden reasoning as proof.

## Deterministic authority

The following must be computed by deterministic services:

- indicator values;
- condition pass/fail;
- readiness/near-match scoring;
- lifecycle transitions;
- alert proof;
- duplicate suppression;
- “Why didn’t this alert happen?” reconstruction;
- universe inclusion and policy decisions;
- billing and entitlement state.

## Bounded Agent Control

The optional agent coordinator is:

- off by default;
- able to run in shadow/no-execution mode;
- limited to small typed tools selected from authenticated server state;
- constrained by ownership, plan, state, hash, timeout, token, step, and cost checks;
- unable to approve, activate, execute, bill, publish, or mutate the registry;
- required to fall back to the deterministic legacy flow if a turn is invalid or unavailable.

## AI-agent truth hierarchy

Agents working on HilalMarkets should prefer:

1. Current production database and approved publication records.
2. Current repository code and migrations.
3. Current implementation reports and verified test artifacts.
4. Approved product and governance documents in this workspace.
5. Current official third-party sources.
6. Strategic hypotheses, clearly labeled as hypotheses.

Never promote a strategic idea to a current feature without implementation evidence.

## Safe agent output pattern

For a question about an asset:

1. State the methodology and version.
2. State the current stored status and review date.
3. Explain the main reasons and qualifications.
4. Identify evidence gaps or use-specific limits.
5. Separate historical event status from current status.
6. Avoid personal investment advice.
7. Link to the Evidence Passport.
8. Escalate factual errors through the report-problem workflow.

For a question about market opportunity:

1. Identify the approved Watchlist and screened universe.
2. Show deterministic readiness and direction.
3. Show present and missing conditions.
4. Show data freshness and evaluation time.
5. State that the user retains the decision.
