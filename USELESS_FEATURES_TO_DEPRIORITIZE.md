# Useless Or Low-Value Features To Deprioritize

This file lists features that may sound attractive but are low value or risky if they
become the center of TraceEdge positioning.

## 1. "AI Creates Alerts" As The Main Claim

Status: deprioritize

Reason:

Competitors already offer natural-language or AI-assisted creation. If TraceEdge leads
with this, it sounds generic.

Better:

Lead with prompt coverage, source-linked rules, proof receipts, and diagnostics.

## 2. Near-Miss As The Main Differentiator

Status: keep, but make supporting

Reason:

Near-Miss is useful, but not enough alone. It becomes stronger when tied to lifecycle,
condition bottlenecks, and proof.

Better:

Position Near-Miss as part of "why it is forming and what is missing."

## 3. Huge Indicator Count

Status: deprioritize as headline

Reason:

TradingView and TrendSpider already have broad indicator ecosystems. Users care more
about whether rules are understood and evaluated correctly.

Better:

Show fewer high-confidence rules first. Mark provider-required and unsupported rules clearly.

## 4. Raw Freeform Canvas

Status: risky

Reason:

A board with many disconnected boxes can look powerful but feel confusing.

Better:

Default to a guided Strategy Board. Keep advanced freeform behavior optional.

## 5. Raw JSON For Normal Users

Status: hide by default

Reason:

Raw schema lowers trust and makes the product feel unfinished.

Better:

Use plain-language summaries, condition cards, source trace, and validation panels.

## 6. Smart-Money Labels Without Deterministic Proof

Status: risky

Reason:

Terms like "order block", "displacement", or "liquidity sweep" can become subjective.

Better:

Only show them if the definition is explicit and proofable. Otherwise ask for clarification.

## 7. Provider-Dependent Filters Before Data Exists

Status: defer

Reason:

Market cap, dominance, token category, and cross-market context can be useful, but
unavailable data creates bad user trust.

Better:

Mark as provider-required and do not activate mandatory unavailable conditions.

## 8. Universe Scanning Alone

Status: not unique

Reason:

Watchlists, screeners, and scanners already exist in competitor products.

Better:

Make universe scanning diagnostic: coverage score, skipped symbols, lifecycle state,
proof receipts, and missed-alert reconstruction.

## 9. Too Many Templates

Status: reduce quantity, improve quality

Reason:

Many mediocre templates create noise.

Better:

Ship fewer high-quality templates with:

- mini-logic preview
- proof example
- expected frequency
- common false positives
- bottleneck explanation
- supported/provider-required badges

## 10. AI Suggestions That Auto-Change Strategies

Status: avoid

Reason:

Auto-changing a strategy damages trust and can create hidden risk.

Better:

Show AI suggestions as visual diffs. Require explicit user approval.

## 11. Execution Bot Direction

Status: avoid for V1

Reason:

It changes security, legal, and trust requirements. It also puts TraceEdge into a crowded
execution-bot category.

Better:

Stay monitoring-first: no exchange trading keys, no trade placement, no profit promises.
