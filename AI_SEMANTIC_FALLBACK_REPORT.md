# AI Semantic Fallback Report

Date: 2026-06-28

## Summary

TraceEdge now has an optional AI semantic fallback layer for unknown prompt fragments. It is guarded behind configuration flags, runs only after deterministic parsing, and cannot make unsupported or provider-required concepts executable by itself.

The AI role is classification only. Deterministic validation still decides whether a condition can enter a strategy.

## What The Layer Does

- Receives unresolved prompt fragments after deterministic parsing.
- Sends only compact context to AI: the original prompt, unresolved fragment, already parsed conditions, known executable capabilities, provider-required capabilities, and default timeframe.
- Requires strict JSON output.
- Validates returned capability keys against the live capability registry.
- Converts a phrase only if the capability exists, is executable, is not provider-required, preserves the source fragment, and passes confidence/safety checks.
- Adds AI-assisted assumptions and prompt coverage metadata.
- Caches results so repeated fragments do not repeatedly call AI.

## What It Does Not Do

- It does not replace the deterministic interpreter.
- It does not invent indicator values, provider data, setup results, market cap, open interest, news, macro, order-book, or cross-symbol evidence.
- It does not bypass provider-required blocking.
- It does not silently accept vague phrases.
- It does not auto-add AI suggestions to the permanent vocabulary.
- It does not execute trades or generate buy/sell instructions.

## Configuration

New environment variables:

- `AI_SEMANTIC_FALLBACK_ENABLED=false`
- `AI_SEMANTIC_FALLBACK_MODEL=gpt-5-nano`
- `AI_SEMANTIC_FALLBACK_MIN_CONFIDENCE=0.85`
- `AI_SEMANTIC_FALLBACK_REVIEW_CONFIDENCE=0.65`
- `AI_SEMANTIC_FALLBACK_CACHE_TTL_SECONDS=86400`
- `AI_SEMANTIC_FALLBACK_MAX_CALLS_PER_PROMPT=2`
- `AI_SEMANTIC_FALLBACK_MAX_FRAGMENT_CHARS=160`

The fallback defaults to disabled. If enabled without `OPENAI_API_KEY`, it fails safely and leaves deterministic interpretation usable.

## Confidence Rules

- `>= 0.85`: may convert only if `safe_to_convert=true`, semantic type is `condition`, and the capability is executable.
- `0.65` to `0.84`: marked as review-needed and blocks required conditions until the user confirms or clarifies.
- `< 0.65`: rejected as too uncertain.

## Provider-Required Behavior

If AI classifies a phrase as provider-required, or returns a provider-required capability key, TraceEdge creates a blocked/provider-required issue. It does not create an executable condition.

Examples that remain blocked unless configured providers exist:

- `open interest rising`
- `positive news`
- market-cap requirements
- order-book depth requirements
- cross-symbol BTC context

## Examples Converted

With AI fallback enabled and mocked safe responses in tests:

- `green candle` can resolve to `green_candle`.
- `positive candle` can resolve to `green_candle`.
- `red candle` can resolve to `red_candle`.

In normal deterministic flow, those examples are already handled by the vocabulary layer, so AI is not called.

## Examples Blocked

- Unsupported capability key returned by AI: rejected.
- Provider-required capability returned by AI: blocked.
- Low-confidence classification: rejected.
- Review-range confidence: review required.
- Malformed JSON or service error: safe failure with deterministic result retained.
- Vague phrase such as `strong coin`: clarification required instead of auto-conversion.

## Prompt Coverage UI

AI-assisted conversions are exposed through:

- `raw_metadata["ai_semantic_fallback"]`
- the normal assumptions list, for example `AI-assisted semantic fallback understood ...`
- prompt coverage metadata generated by `audit_prompt_coverage(..., ai_interpreted=True)`

The existing dashboard coverage panels render assumptions, unsupported/provider-required issues, mapping rows, and source traces. A dedicated visual badge for AI-assisted rows is still a UI polish task.
